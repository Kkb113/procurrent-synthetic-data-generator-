Procurement Data Generator

Run the validated Procurement backend pipeline from metadata, ERD, scenario, and an LLM generation plan.

Inputs

Procurement v2 is the active Procurement model

Use SupplierMaster, SupplierComponent, ComponentMaster, Plant, Warehouse, PurchaseRequisition, PurchaseReqLine, RFQHeader, RFQLine, SupplierQuotation, SupplierQuotationLn, PurchaseOrderHdr, PurchaseOrderLine, POSchedule, ShipmentHdr, ShipmentLine, GoodsReceiptHeader, GoodsReceiptLine, IncomingInspection, InspectionResult, InventoryReceiptDetail, InventoryTransaction, Inventory, SupplierInvoice, and PaymentTransaction.

InventoryReceiptDetail captures receipt-level supplier, component, PO, receipt, date, and price variance traceability. InventoryTransaction is the inbound StockIn ledger sourced from InventoryReceiptDetail. Inventory stores the calculated stock balance by Component, Plant, and Warehouse. InventoryBalance is not part of v2. Procurement v2 uses 2025 dates, US locations, USD values, one Plant, and one Warehouse.

Production v1 runs from the dedicated command-line pipeline

Production v1 is a Production Execution module within MES context. It consumes Procurement final_data and generates production orders, material issues, batches, operations, quality, finished goods, genealogy, and cost summary through scripts/run_production_pipeline.py. It uses the single upstream Plant and Warehouse, ShiftCode A only, and still allows multiple WorkCenters.

The UI does not expose Production as an active pipeline option yet. Use Procurement v2 here, then run the dedicated Production pipeline from the command line.
